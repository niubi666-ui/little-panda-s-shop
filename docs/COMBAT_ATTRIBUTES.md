## 3. 三种伤害与具体归类

| 来源 | v1 类型 | 说明 |
|---|---|---|
| 普攻三段、翻滚斩、R 重击、右键剑气、测试箭 | 物理 | 剑气的形态不自动赋予魔法类型。 |
| 冰/火/土/雷元素附着后的上述攻击 | 保持本体类型 | 核心负责附着；不自动转伤、不额外赠送一笔元素直伤。 |
| 贯穿、回旋、分裂 | 继承父载体 | 分裂有原 rank 伤害比例；贯穿/回旋沿用现行命中次数与去重。 |
| 命中爆炸 impact_blast、旧测试连锁 chain | 魔法 | 取父攻击减伤前公式基数乘现有比例；不继承暴击伤害。 |
| 火焰灼烧、雷电放电 | 魔法 | 各次 tick/放电分别结算，不自动再次触发元素。 |
| 蒸汽、过载、熔岩、超导、磁暴 | 魔法 | 主目标、周围伤害、熔岩 tick 分别有 profile。 |
| 冰土碎冰反应 | 物理 | 保留“土命中有效冰冻窗口”的前置；不是任意冰土接触就触发。 |
| 火/冰/雷同元素专精爆发 | 魔法 | 继续遵守既有传播次数与来源限制。 |
| 土同元素专精爆发 | 物理 | 土元素的普通附着本身仍只产生既有碎甲/失衡效果。 |
| 弩箭、冲锋、游侠快箭/多重箭/箭雨/蓄力箭 | 物理 | 连射与组合招式复用对应单次攻击 profile。 |
| 游侠蓄力箭留下的地面裂隙 | 魔法 | 独立 tick，不重复计算蓄力箭本体伤害。 |
| 真实伤害 | 本轮只接通结算与测试 | 不把某张现有卡擅自改成真伤；以后由配置明确指定。 |

碎冰追击、乘隙斩、破冰重击是**原命中的条件倍率**，不是新增一笔冰伤。蓄力改变公式基数。霜径只减速，冰衣只加盾，冰爆载荷只挂状态；伤害类型分类不能让它们凭空获得伤害。权重为零或测试专用的旧卡继续保持原可用性，本轮不重新上架。

### 公式与成长

- 物理/魔法：`减伤倍率 = K / (K + 对应抗性)`，K 从配置取，首版 100；抗性首版最低 0，暂不做负抗、穿透或抗性削减。面板减伤为 `1 - 倍率`。
- 真实伤害：跳过护甲、魔抗及普通增伤/减伤/易伤；仍被无敌拒绝、被通用护盾吸收，首版不暴击。基础公式可以拥有自身明确的 AD/AP 系数，不能因此偷偷套用普通增伤。
- 直接攻击：`基础项 + 攻击力×系数 + 法强×系数`。玩家攻击力 20 时，普攻系数 0.8/0.9/1.5、重击 2.1、剑气 1.2、翻滚斩 0.8，得到当前 16/18/30、42、24、16。游侠箭为 0.6/0.8/0.4/2.5 AD，裂隙为 0.4 AP。
- 元素/反应/专精：保留现有基础金额、层数和对应强化；统一乘 `1 + 正额外攻击力×0.01 + 法强×0.02`。正额外攻击力是最终攻击力超过该 actor 基础攻击力的部分，最小 0。该系数也在 JSON。初始玩家 AD20/AP0 时倍率为 1；增加 AD20 或 AP10 时均变为 1.2。支持战士顺带强化元素，也支持以后专注法强；不要求两项都投。
- AP 系数和伤害类型独立：土专精可有 AP 成长但造成物理伤害。物理、魔法、元素标签各是独立维度。
- 保持现有 `power/action_power/核心二级damage_bonus` 对武器动作的加法关系，统一只应用一次；`power` 暂不扩成对所有元素 tick 的增伤。UI 明写“武器伤害加成”，不能装作攻击力提高。元素强化、反应强化另走自己的加成，不叠乘一次同名全局倍率。
- 元素配方先把当前同字段强化加入基础字段，再按层数计算；反应配方先算基础项/每层项，再乘一次对应反应强化；专精读取当前所选 rank。以上均在 amount recipe 内完成，再乘属性成长，统一执行器不重复加一次这些来源强化。
- 全局元素/反应强化与源角色属性按当前值读取，已经存在的灼烧也能受益。熔岩区已改为存来源/配方 ID，tick 时读取当前伤害强化。区域位置、已确定的持续时间和半径不因调伤害而重建。

## 4. 架构与一次命中的结算

沿用 content → combat → app → presentation 的分工，不另造全局管理器或任意 JSON 脚本语言。实现三个小职责即可，文件名可按现状调整：

1. **属性解析/容器**：基础定义 + 带 source_id 的 modifier → 最终属性只读快照。修改器可移除/替换；同 source/stat/operation 不重复注册。常规顺序为 `(base + flat之和) × (1 + percent之和) × 独立倍率`，最后按配置限幅；暴击率/冷却恢复按小数百分点加法。基础中性值、上下限和共享预设均来自配置。
2. **伤害配方/请求**：公式算出分量；携带 source_handle/team/runtime_id、room_generation、root_id、event_id、ability/action/profile ID、origin、暴击结果与触发权限。只用有限 formula/provider 枚举，不能 eval 配置字符串。
3. **伤害执行器/结果**：统一过滤友军、死亡、跨房来源和无敌，再算各分量，提交一次护盾和生命变化，发布一次命中事实。返回每种原伤/减伤、吸盾、实际掉血、有效命中和暴击信息，UI读取结果。

正常流水线：公式 → 来源增伤 → 合法直接命中条件增伤 → 暴击 → 目标易伤/减伤 → 对应抗性 → 护盾 → 生命。真实分量跳过声明不支持的阶段。混合伤害按类型分别减伤，之后合并提交；不能因为有物理和魔法两分量，重复触发元素、反伤、受击、击退、失衡或击杀。

### 必须明确的继承与边界

- 普攻每一段、重击、剑气各自提交时产生 root；每 root 只抽一次暴击，范围目标/贯穿/回程/分裂共享结果。分裂不重新抽奖。爆炸、元素 tick、反应、专精首版不暴击。战斗暴击用独立随机流，不占选卡或视觉 RNG。
- 派生依据是明确保存的**父武器公式基数**（含蓄力、已有派生比例，不含条件追击、暴击、目标减伤、吸盾、实际掉血）。派生自己的合法增伤只算一次；禁止用 `min(applied_damage, context.damage)` 当新伤害种子。高护甲或濒死主目标不能压低周围爆炸/连锁的原伤。
- 分裂/回程/爆炸保留原 origin、预算、去重和元素载荷权限。既有碎冰追击只认可同动作较早独立施放，乘隙斩只认可另一正式动作的窗口；不能借继承把这些加成传播给分裂/爆炸。
- 移除旧 ElementEffects.incoming_scale 和 CombatActor.receive_hit 中重复的倍率落点，迁为统一执行器的一次结算；土/冰/超导易伤按现有加法，破防易伤单独只乘一次。Boss 控制窗口及其来源证据保持。
- 护盾完全吸收的合法攻击仍算命中，回传“有效命中/吸盾”与“实际掉血”两个事实；无敌拒绝则不挂元素、不触发反击。禁止所有 on-hit 都用 `hp_loss > 0` 判断。
- 失衡采用合法命中的非暴击、抗性与护盾之前的冲击基数；土失衡加成另加一次。不要把物理 armor 接到现有 `armored()` 霸体判定，也不要让新增护甲自动拉高破防所需刀数。
- 持续效果必须记住实际来源，不能在 DamageExecutor 中假定来源永远是玩家。来源失效、死亡和切房按当前存活/清理策略处理，不凭空回退到 player；同元素来自多个动作时保留既有归属规则。
- 可破坏场景道具仍需工作：用显式零护甲/零魔抗的 damageable 适配定义，生命读取已有道具配置。不能要求每个道具都拥有完整角色组件，也不能保留一个默认为真实伤害的旧 float 入口。

## 5. 攻速、冷却与跨房

- 攻速缩放明确允许的动作前摇/有效段/后摇及其取消窗口，动画和命中时间同步；普攻再次可用计时也只缩放一次。不能只把 AnimationPlayer 播放快而逻辑不变。
- 重击/剑气冷却与闪避充能采用 `原冷却 / (1 + 冷却恢复)`；攻速不能再缩短同一冷却。蓄力等待、位移距离、投射物速度、控制持续、元素 tick、卡牌内部触发 CD 不自动受这两项影响。采用动作提交/冷却开始时快照，避免修改属性突然跳阶段。
- 敌方需要复用现有时间轴与旗手加速，把旗手增益转为带来源的 modifier，删除旧重复加速。前摇下限在配置逐项列出；游侠蓄力警告仍保持原时长。连发和组合技能沿用组成招式的下限。
- 前摇下限迁入新表后，弩手/冲锋原 `minimum_windup_sec` 同步改引用或删除重复字段，不能两处分别调参。缺少时间策略的新增攻击要在内容检查时报错，不从代码猜一个下限。
- encounter 的生命、伤害倍率仍取现有配置：实例最大生命乘一次，伤害使用独立 spawn_damage_multiplier 乘一次。不再同时改 AD/AP、复制能力伤害以及 role_damage。护甲/魔抗不额外随深度增长。游侠新 HP450，现有三档 Boss 为 450/720/1080，物理有效生命接近原 500/800/1200。
- 跨房先重建基础属性和构筑 modifier，再恢复当前生命并钳制上限。调整最大生命默认保持当前绝对 HP，上限下降才钳制；若奖励要同时治疗，明确发出治疗效果。开关 UI、重建属性、切房都不能额外回血。

## 6. C 角色属性页面

- 新增 `ui_character_stats` 动作，默认 C；当前没有按键冲突。保持现在左键普攻、R重击、右键剑气、Shift闪避，不恢复历史 Q 布局。按键进入项目现有输入配置，面板样式放 Resource/场景，双语文案放 locales。
- 训练场与正式房间内可用；地图/选卡/过场等模态期间不得互相覆盖。C 打开/关闭，Esc 只关最顶层属性页；不能顺带打开设置或解除别人的暂停。店铺当前如无战斗实体，提供明确“基础属性”预览；没有本局实体时不伪造局内实时增益。
- 打开时冻结规则、投射物、敌人、区域、动作、VFX，复用现有暂停入口；面板自身可操作。取消尚未提交的输入意图和按住状态；关闭后恢复原暂停与焦点，不补放缓存攻击/剑气/翻滚斩。已提交的战斗动作按原暂停进度继续。
- 主区展示最终十属性，另列当前/最大生命、当前护盾、物理/魔法减伤百分比；详情可以展开基础值及来源增益。仅物理/魔法减伤是派生展示，不再单独存“物抗%”属性。
- 技能区列普攻三段、重击、剑气的**减伤前、未暴击基础伤害**及类型，另写暴击倍率、条件加成和元素效果。条件未触发时不算入常驻伤害，不能把 DoT 总量或反应伤害误算作每次直击。计算预览调用同一纯公式，不另写 UI 算法，不消耗 RNG。
- 角色攻击力不会因 `power` 武器增伤卡变化，所以需附“武器伤害加成/动作加成”说明，避免面板看起来卡没生效。语言切换、选卡后、加/减 buff 后，以及重新进房时数值正确刷新。

## 7. 验证与当前边界

本轮实际通过：内容/schema/翻译一致性；`combat_attributes` 36 项；`attribute_damage_paths` 143 项；Forward+ `character_sheet` 23 项（训练/正式房间/店铺、中英文截图、飞行中剑气暂停与输入隔离）。另通过游侠基础/组合/蓄力、五波训练、三区 Boss 实际生成、道具交互破坏、冲斩 823 项、右键预输入 484 项、冰协同 147 项、无敌开关和原冲锋结束回归。完整旧测试库未逐项运行，遗留项见 STATUS。

`ice_synergy` 原 4 项失败来自过早等待和旧靶位，测试现已按现有挥刀时序及新增减伤修正；没有为测试改变冻结/追击规则。选卡流程测试等待新版收起动画后再购买，退出场景时不再启动已离树的选卡动画。

已覆盖的关键验收：

- 配置中每种 actor、每个伤害入口、全部 51 个现有 upgrade 均有明确策略；所有 profile 引用有效。修改 JSON 能改变实际结果，不改代码。
- 100 物伤对 100 护甲实伤 50；魔伤对 100 魔抗同理；100 真伤无视上述抗性及普通增减伤，30 通用盾后掉血 70，无敌时为 0。
- 同一命中 80 物伤 + 20 魔伤，对护甲100/MR0/盾10：吸盾10、掉血50、命中事件只有一次。足够生命下检查，不用残血截断掩盖错误。
- 分裂/回程共享暴击；爆炸不吃父暴击，不会在高护甲/残血主目标处被二次减伤。物魔各自正确经过对应抗性。
- 已存在灼烧/熔岩可读到后续全局强化；既有冰冻结窗口、碎冰追击、乘隙斩、霜径和冰衣的来源限制及 Boss 兼容保持。
- 旗手不重复加速；新护甲不延迟失衡阈值；深度倍率不平方叠加；跨房不回满血。
- C 中所有战斗时钟冻结，C/Esc/L 与原面板协调，关闭无残留输入；中英文面板数值与实测伤害一致。输出 UI 截图与实际跑过的验证，剩余问题明确列出。

尚未完成：正式数值平衡、完整冒险的人工作战试玩、装备/属性点成长和新真伤技能。非玩家来源在定向测试中有效，但没有因此新增场景火桶、敌人元素攻击或任意环境反应系统。旧 `power` 仍是武器增伤，禁用卡没有重新上架；现有占位表现沿用。
