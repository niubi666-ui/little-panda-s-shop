# 敌人分工与预算遭遇原型

更新：2026-10-03。五种普通兵种之外，新增[精英游侠训练切片](ELITE_RANGER.md)：通过训练工具单独刷新，三种箭技、有限翻滚和实际骨骼动画；不加入下方普通遭遇池。五种普通敌人的基础行为与历史验证保持2026-09-27记录。

## 控制状态接入（2026-10-01）

现有五类敌人均消费统一控制许可。减速影响移动和冲锋速度；冻结取消近战/重型前摇、弩手未发射攻击和冲锋，抑制旗手光环；已飞出的弩箭继续。具体刷新/免疫/时长策略与本轮测试见 [命中机制](COMBAT_MECHANISMS.md)。下方2026-09-27记录是历史基础行为，冻结硬控可取消重型普通受击不可打断的前摇。

## 当前玩法

敌方单位彼此取消实体碰撞，冲锋、追击、撤退不会被友军身体拦住；敌人与玩家、墙体、可破坏物和宝箱仍碰撞。敌人可能相互穿过或重叠，这是当前确认的规则。角色工厂沿用 `combat_actor.configure()` 的阵营碰撞层，不再统一覆盖为同一层。

| 敌人 | 行为 | 应对方式 |
|---|---|---|
| 斥候 `scout` | 原近战追击与扇形挥击 | 拉开、绕后、打断 |
| 重型 `brute` | 原地大范围蓄力横扫，蓄力不可打断 | 离开扇形，利用后摇 |
| 游击弩手 `crossbow` | 安全距离 4–7 m；10 m 内可射击；基础 1.5 s/次、0.45 s 预警；9 m/s 红球；贴近则后撤，无近战 | 利用掩体、横向移动，近身快速击杀（28 HP） |
| 冲锋矛兵 `charger` | 2.5–12 m 进入冲锋准备；0.8 s 红色直线预警，矛后收；15 m/s 直线冲刺、最长 10 m；结束后 1 s 硬直 | 侧闪后反击；可受击打断；撞墙或撞人提前结束 |
| 督军旗手 `banner` | 中后排保持距离，贴近缓慢退开；周围 8 m 友军攻速/移速各 +30%，脚下红圈 | 优先击杀或将敌人拉出范围（35 HP） |

- 弩箭/冲锋在预警开始锁定方向，不追踪拐弯；弩箭有飞行时间、连续路径命中和实体遮挡，不是瞬间扣血。
- 矛兵每次冲锋至多命中一次；受击硬直立即取消后续冲锋命中，撞墙不穿越、不沿墙继续滑冲。成功命中才击退，玩家闪避无敌期间不扣血或击退。
- 光环不增强自身，多个旗手取最高加成，不叠加。移速、范围标记在死亡/离开范围后移除；已开始的攻击使用开招时的攻速快照，新攻击立即恢复普通速度。+30% 攻速表示时长除以 1.3，而非减去 30%。
- 旗手可令重型蓄力从 1.15 s 缩短至约 0.885 s。弩手、矛兵另有最小预警下限；矛兵冲锋速度/距离与完整 1 s 硬直不随光环加速。
- 现有构筑伤害/击退可以作用于新敌人。敌人投射物属于独立敌方执行器，不触发玩家 Build 的派生链。

## 试玩入口

从当前 Godot 工程运行，店铺 **F6** 进入战斗。

- 左侧「训练深度」默认 **6**；「应用深度 / 新遭遇」保持本房家具布局，重抽敌人阵容。
- 「重新训练」保留布局、遭遇阵容和预滚掉落，重置临时状态。
- 「新随机布局」重抽房间物件与遭遇，保留所选深度。
- 默认两波；现有三选一构筑奖励流程仍生效。灰盒回归场景继续使用原固定两波，保证旧战斗验证可重复。
- 顶部「训练工具」可启用玩家/敌人伤害无敌、恢复生命、追加敌人；「界面显示」管理训练面板，详见 [训练工具](COMBAT_PROTOTYPE.md#训练工具与界面显示)。

建议对比：

1. **斥候＋弩手＋矛兵**：持续横向移动，观察直线冲锋的惩罚窗口；优先靠近脆弱弩手与直接输出斥候的风险区别。
2. **旗手＋重型**：比较先杀旗手、以及先打重型时的蓄力速度。
3. 将敌人引到墙另一侧，验证弩箭被挡、敌人调整路线。

「玩家是否主动改变走位/击杀顺序」仍需人工试玩判断。自动测试验证了不同应对产生不同结果，不将自动测试等同于主观手感验收。

## 预算与合法组合

`data/rooms/encounters.json` 是唯一内容入口：12 种手工合法阵容，整组加权抽取，不逐只任意抽怪；同一房间优先不重复阵容。普通两波使用房间的3个出生点作为容量约束；训练工具的额外敌人会在这些点附近检查可用位置，并受独立同时存活人数限制。

| 起始深度 | 预算 | 原型人数上限 |
|---|---|---|
| 1 | 3 | 3 |
| 3 | 4 | 3 |
| 6 | 5 | 3 |
| 10 | 6 | 3 |
| 15 | 7 | 3 |

实际预算花费必须达到所在档的 80%，且不超预算。斥候成本 1、重型 3、其余 2。远程、冲锋、支援分别最多一只；弩手必须有配置指定的斥候护卫，不允许纯旗手阵容。没有合法组合则报告错误，不偷偷塞随机敌人。深度 15 以后暂保持最后一档，面板最多 30，后续扩充曲线不需要改执行器。

种子通过独立 SHA256 流驱动遭遇与每个敌人的掉落。改掉落版本不改变阵容抽取。入房锁定版本、预算、阵容、敌人稳定槽位和掉落计划；重开校验计划与当前种子/配置一致，旧版本或篡改计划拒绝复用。未接入正式冒险存档。

## 训练追加敌人

「追加一波敌人」使用现有`EncounterPlanner`，按进入本房时锁定的深度抽取一个合法组合；不把场上旧敌人替换，也不重新抽Build。额外序列与原始遭遇、掉落、三选一奖励RNG隔离，只有整组成功生成才推进序号。原始锁定计划保持不变，额外敌人不发掉落，不重复发已经完成的波次奖励。

生成前按身体尺寸检查可行走地面、世界障碍、玩家/现存敌人及本次待生成成员。在原出生点附近有限网格搜索；超过存活上限或任一成员找不到位置，整组拒绝并提示原因。上限当前为18，只限制训练追加，合法单组的预算/角色限制仍来自原配置。

成功追加时清理已死亡实例，并移除引用死亡弩手的在途箭；活敌的AI、投射物和玩家Build保持运行。开启敌人无敌后，额外敌人与之后自然生成的下一波均继承开关。

胜利后可追加继续练习，保留现有Build；死亡时禁用追加，需重新训练。重试只恢复原始锁定遭遇，清空额外敌人、无敌开关与菜单显示偏好。这些状态不进入正式存档。

`data/rooms/encounters.json`现为`schema_version=2`、`content_version=encounters.2-training-tools`，`generation_version=1`保持原抽样算法。新增必填`training_tools`：

| 字段 | 含义与校验 |
|---|---|
| `max_alive_enemies` | 同时存活人数上限；整数1–60，且不得低于任一`depth_bands.max_enemies` |
| `spawn_search_radius_m` | 原出生点周围搜索半径，0.01–20米 |
| `spawn_step_m` | 搜索步长，0.01–20米，不能大于半径；半径/步长不得超过8，限制网格枚举规模 |

上述值直接从只读`EnemyCatalog.encounters.training_tools`注入训练工具；缺字段、未知字段或非法数值均拒绝加载，没有代码默认值。旧schema及不匹配的锁定内容版本不会静默复用；这不提供正式存档迁移。

## 配置与代码边界

| 路径（相对 game） | 修改用途 |
|---|---|
| `data/combat/prototype.json` | 角色生命/基础移速/受击硬直；原近战与重型技能 |
| `data/enemies/roles.json` | 行为角色、预算成本、距离/前摇/弹速/冲锋/光环参数、掉落表 ID |
| `data/rooms/encounters.json` | 深度预算、合法组合、权重、人数/角色限制、测试深度、训练追加搜索参数 |
| `data/loot/enemies.json` | 独立概率掉落条目与数量区间；当前测试草药和矿石 |
| `data/schemas/*enemy*.json`、`encounters.schema.json` | 配置结构；加载器另检查引用、范围顺序和组合语义 |
| `content/enemies/` | 一次校验、深层只读目录；不按帧读文件 |
| `combat/enemies/*_brain.gd` | 每个兵种的小型状态机，通过显式导航/视线接口调用 |
| `combat/enemies/enemy_runtime.gd` | 本房光环、连续投射物碰撞、冲锋命中协调 |
| `rogue/encounters/encounter_planner.gd` | 纯数据阵容/掉落计划，无表现节点依赖 |
| `presentation/combat/enemies/` | 白光、红线、红球、红圈；不决定伤害 |
| `presentation/combat/{crossbow,charger,banner}_presentation.tres` | 模型与身体碰撞映射 |
| `app/combat_training.gd` | 工厂注入、物理查询适配、波次和界面连接 |
| `app/training_tools.gd` | 临时无敌/恢复/追加命令、额外序列、训练界面显示状态；不拥有永久奖励 |

## 后续更换模型和掉落

- 只换各兵种 `*_presentation.tres` 的 `visual_scene`，校准 `body_shape`/`body_height`。占位模型有名为 `Weapon` 的 MeshInstance3D，用于白光与矛后收；正式骨骼模型可在表现适配器中改挂点，AI 不查找骨骼/动画。
- 攻击由逻辑状态推进，动画只读状态。不会因为动画资源未准备好阻止战斗。
- 掉落表已校验、按种子预滚；死亡只发出 `enemy_loot_ready(spawn_id, enemy_id, drops)` 局部事实，一次死亡只发一次。**尚无敌人物品掉到地上的模型、拾取或永久背包入账。** 后续由 app/session 消费该事实，通过候选提交处理库存及保存失败，不在敌人脚本里加钱。
- 修改已发布阵容、行为或掉落时，更新相应 `content_version`。临时训练死亡槽位 ID 不替代未来完整 Run/Room 的持久身份。

## 实际验证

### 2026-09-27 冲锋贴障碍卡死修复

- 复现原因：蓄力结束切换为冲锋的那一帧没有发出冲锋移动，随后命中处理读取到原地贴墙的碰撞，立即重新进入硬直，反复开冲也无法脱离。
- 现在进入冲锋的同一帧提交移动；强制直线运动使用停止式碰撞，不再沿柱子或墙角滑行。碰撞结果由移动模块报告本帧结果，避免使用旧的滑动碰撞。
- 开冲前按完整身体胶囊检查世界障碍，中心射线能通过但身体过不去时先绕路；近距离被墙隔开时也优先绕路，不一味向后退。
- 新增 `tests/charger_obstacles.gd`：真实庭院种子 7，从不同方向冲向柱座、断柱、花盆、矮墙等共 10 个有效接近情况；验证碰撞后结束、不爬升、恢复后离开障碍。修复时序前 8 个脱离检查失败，修复后 10 个全部通过。日志 `builds/charger_obstacles_fixed.log`。
- `enemy_roles.gd`、`combat_rules.gd`、图形模式 `enemy_training.gd` 回归通过；未生成 Release。

- 内容 schema/语义、226 个双语 key 校验通过。
- `tests/enemy_roles.gd`：360 个深度/种子计划、成本/人数/类型覆盖、确定性、掉落流隔离；真实移动验证侧闪避冲锋/站桩受击、墙阻挡弩箭与冲锋、受击中断射击、旗手不叠加及死亡后恢复。
- `tests/enemy_training.gd`：真实庭院三种新敌人、预警及红球、暂停、重开保留阵容/掉落、深度重抽保留物件、新布局保留深度、双语/面板边界、旗手死亡一次掉落事实、通关/死亡清理。日志 `builds/enemy_training_tests.log`。
- 原 `combat_rules.gd`、`build_runtime.gd`、`room_props_integration.gd` 回归通过，日志前缀 `builds/enemies_`。
- 图形退出仍有原先的 7 个 Texture RID 警告，本轮不宣称解决该问题。没有进行 Release 导出。
