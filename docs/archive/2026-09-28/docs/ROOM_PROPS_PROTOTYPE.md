## 试玩

- 店铺 F6 进入战斗，完成开场三选一后可操作。
- 木桶、板条箱、长板条箱、板条箱堆：**1 HP，普通近战命中一次破坏**，木屑飞散，阻挡移除。
- 石质残墙：不可破坏，阻挡玩家、敌人及直线攻击。
- `chest1`、`chest2`、`forest_bag1`：靠近按 **F** 搜刮，显示本次训练获得的测试草药、测试矿石；再次交互不重复发放。
- 右下角显示种子与战利品。“重新训练”保留实际布局及预先生成的奖励，重置敌人、Build、破坏及搜刮状态；“新随机布局”创建新种子并重开训练。从商店重新进入也生成新种子。
- 清场后可继续移动、破坏箱子和搜刮。暂停、三选一及失败时不能搜刮。
- 本次搜刮是**临时训练状态**；不加入店铺库存、金币或正式存档。

## 模块与权威数据

| 路径（相对 game） | 职责 |
|---|---|
| `data/rooms/props_prototype.json` | 类别、HP、数量目标、候选、间距、尝试上限、通行余量、搜刮距离、测试掉落 |
| `data/schemas/room_props.schema.json` | 必填字段、类型、范围；启动前验证及离线完整 schema 验证 |
| `content/rooms/` | 校验引用与语义，发布递归只读目录；不依赖战斗运行时 |
| `rogue/rooms/prop_planner.gd` | 纯规则规划、独立随机流、网格占用、连通性检查 |
| `rogue/rooms/placement_surface.gd` | 模板提供可行走矩形与随机区域，坐标由 Resource 授权 |
| `app/session/training_loot_session.gd` | 候选状态、提交适配器、搜刮/破坏幂等；提交失败不更改权威值 |
| `app/training_room_props.gd` | 工厂组装、攻击接入、F 交互、绕障服务与局部界面协调 |
| `presentation/rooms/props/` | 模型组合、碰撞体尺寸、木屑表现、界面；共用原字体与 Theme |
| `presentation/rooms/forest_courtyard_v001/placement_surface.tres` | 当前平坦庭院的内侧网格、全庭院摆放区域和中央目标区域，避开固定神龛与花盆 |

房间通过 `runtime_prop_container()` 暴露容器；`RoomPresentation` 注入摆放面和物件表现集。房间模型脚本不自行抽随机数。战斗宿主不包含本模板 ID、资源目录或密度数值。

`MeleeResolver` 增加可选命中筛选器；`MeleeBrain` 增加可选寻路和视线接口。旧训练夹具不注入这些接口，原规则保持。箱子使用独立命中目标列表与负数句柄，不成为敌人、波次计数或击杀奖励，不触发命中敌人的连锁 Build。敌人通过注入的网格路径绕障，路径缓存限于每名敌人的当前起终点；破坏后重新计算占用。

## 随机与可达性

- `SHA256(seed|template_id|generation_version|stream)` 的前 15 位十六进制派生随机流种子。
- `props` 负责放置；`loot/实例ID` 分别决定奖励，入房前固定。表现粒子不消耗这两类随机流，Build 抽取也不共享它们。
- 计划保存：字符串种子、模板/生成/内容版本、实际实例 ID、物件 ID/类别、位置、连续 yaw_radians 朝向及实际奖励。数据为可序列化值；后续存档应保存完整计划，不能仅凭种子跨版本重生成。
- 出生点保留空地；碰撞投影按角色通行余量膨胀。每次接受一个候选前检查所有可行走网格连通，以及出生点与搜刮站位可达。
- 先打乱各类物件的生成请求，中央优先尝试放置 2–3 件随机类型物件；其余请求优先保留搜刮容器，再布置其他物件。数量区间是放置目标；达到配置的尝试上限后允许省略未能安全放下的物件，使用已验证的稀疏方案，日志记录 `omitted`。不无限重试、不强塞障碍物。
- 当前导航面只覆盖已确认没有固定障碍的内庭区域。扩展到新模板时必须重新制作摆放面；此原型不支持斜坡、楼层、任意固定障碍自动栅格化。

## 已验证

- 40 个种子：同种子重复结果一致；实际布局 JSON 往返；出生点/通路连通；三种搜刮容器均保留；八种表现变体都出现。v002实际每房 11–14 个物件，40 个种子均有至少 2 件中央物件，且三种搜刮容器均保留。
- 提交适配器修改候选后失败：权威状态不变；成功后适配器也不能污染权威值；重复搜刮/破坏拒绝，未知实例拒绝。
- 真正的近战时间线与命中器打坏 1 HP 箱子、移除碰撞；石墙受击保持；F 搜刮、距离限制、中英文、重复按 F 不重复奖励。
- 实际 CharacterBody 敌人绕过随机石墙到达玩家一侧；重开保留计划、新布局更换计划。
- 森林战斗/Build/店铺控制/ESC 设置回归及导出结果见本次 `builds/room_*` 日志。
- Windows Release EXE 从项目外独立启动进入商店成功；导出 PCK 从项目外执行真实物件/寻路/F交互/重开测试通过。程序位于 `builds/windows-release-room-scatter/LittlePandasShop.exe`，必须与同目录 PCK 一起使用。

## 明确边界与下一步

本轮随机的是**同一个模板内的物件布局**。随机房间池、随机敌人组合、深度曲线、正式冒险/存档主种子、跨房间战利品和回店结算仍待实现。三个搜刮箱的测试奖励不是最终经济设计。

普通近战可破坏箱子；现有剑气碰到这些实体时停止，尚不把箱子当作技能伤害目标。后续应明确哪些主动/派生技能允许破坏物件，再扩展统一目标能力协议，避免箱子成为连锁、击杀或吸血的刷取来源。搜刮目前无开盖动画，使用“已搜刮”提示；未制作正式音效、打开界面或掉落拾取动画。

图形退出仍可能出现此前记录的 7 个 Texture RID 警告；森林多次切换诊断还出现 7 个 ObjectDB 退出泄漏警告，与此前切换诊断一致，本轮没有将其当作已修复。


## v002：中央覆盖与不规则分布

- 旧版的左右窄区域、0.5 米位置吸附和90°朝向限制均已移除。全庭院连续取点，随机朝向覆盖一整圈；网格只负责导航和通行检测。
- JSON 新增中央目标数量、中央尝试上限、聚簇概率和聚簇半径。45%的候选提案尝试围绕已有物件在1.5–2.8米环带内取点，其余在全区取点；这是候选概率，经过碰撞/通路筛选后的实际比例会变化。
- 采用按物件尺寸排斥重叠的拒绝采样，混合中央覆盖、小簇与散点；不是完整 Bridson 泊松盘实现，不追求物件均匀铺满。中央尝试上限后允许回到全区候选，最终仍须通过通路检查。
- 出生点采用点到碰撞外包矩形的圆形距离检测，保护距离1.35米；物件间留白0.2米。旋转后重算保守 AABB，再用于重叠、出生保护和网格占用，避免视觉转了但碰撞校验没转。
- schema_version / generation_version 均为2，content_version为 room-props.2。旧计划不会按新字段默默解读，跨版本注入仍明确拒绝。店铺家具的网格旋转规则未改。
- 验证日志：`builds/room_scatter_rules.log`、`builds/room_scatter_integration.log`；实机比较为 `docs/previews/room_scatter_seed_7.png` 和 `room_scatter_seed_91.png`，截图隐藏测试HUD以便检查摆放。

参考：[Red Blob Games散点分布比较](https://www.redblobgames.com/x/1830-jittered-grid/)阐述了网格、抖动与泊松盘的分布差异；[Two-step Constructive Approaches for Dungeon Generation](https://arxiv.org/abs/1906.04660)将房间结构与物件布置分阶段处理。本项目沿用分层结构，使用自身的物件尺度/通行约束作取舍。
