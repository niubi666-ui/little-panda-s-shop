# 三选一与 Build 构筑原型

更新：2026-09-28。内容版本以 manifest 为准，Build schema_version=1。这是已经接入真实战斗的训练切片，正式技能名单由后续设计替换。

## 试玩

1. 在店铺按 **F6** 进入训练。开场显示三张升级卡，点击其中一张继续。
2. 第一波清场后再选一次；左侧“当前构筑”显示已选等级。
3. 点击 **“测试：再抽三选一”** 可连续取得升级，方便快速测试组合。
4. 选择期间战斗、AI、子弹和表现计时暂停；**L** 切中英文保留原候选。Esc不能跳过必选奖励。
5. 重新训练或返回店铺会丢弃本轮构筑。全部升级满级后给出提示，仍可继续战斗。

| 测试升级 | 实际作用 |
|---|---|
| 锋刃强化 | 提升普攻伤害；剑气继承施放伤害，派生不重复乘倍率 |
| 轻盈步伐 | 提升正常移动速度；不改变闪避速度或击退冲量 |
| 挥刀剑气 | 每次普攻生效时发射投射物；挥空也能发射，碰墙或首次接触敌人结束 |
| 回响连锁 | 普攻或剑气实际造成伤害后，从该目标向附近敌人连锁；每次施放最多触发一次 |
| 剑气分叉 | 取得剑气后才进入候选；命中后分成多发，继承剩余寿命、伤害快照和共同预算 |

本轮共5项测试升级、14级。等级提升替换该升级的旧级参数，不把每级完整参数重复相加。卡片展示的是**下一级的完整效果**。链式伤害以实际扣血量为起点，并逐跳衰减；致死过量伤害不会放大连锁。

右侧“刀光测试”继续只负责美术选择，与左侧真实构筑独立。当前剑气球体和连锁线条为可替换的临时表现。

## 模块与维护入口

| 路径（相对项目根） | 职责 |
|---|---|
| `game/data/builds/prototype.json` | 唯一玩法参数源：候选池、等级、前置、标签、互斥、权重及预算 |
| `game/data/schemas/build_prototype.schema.json` | 构筑内容 schema_version=1；现有战斗schema仍为2 |
| `game/content/builds/` | 严格加载、引用校验与递归只读目录 |
| `game/rogue/build_offer_sampler.gd` | 按权重无放回，过滤满级/前置/标签/互斥，显式fallback |
| `game/combat/builds/build_resolver.gd` | 从已选等级编译只读执行计划；按稳定ID排序、限制属性范围 |
| `game/combat/builds/build_runtime.gd` | 施放快照、派生任务队列、投射物扫掠、连锁和分裂 |
| `game/combat/builds/build_sweep.gd` | 平面目标接触距离算法；墙体查询由app注入 |
| `game/app/session/training_build_session.gd` | 候选/RNG/选择结果的隔离提交、防重复与失败回滚 |
| `game/app/training_builds.gd` | 训练内存提交适配器、奖励队列、UI与战斗连接 |
| `game/presentation/builds/` | 三选一、当前构筑、派生效果显示；Resource控制皮肤/几何/材质 |
| `game/data/locales/{zh_CN,en}.json` | 文案人工源；PO由内容工具生成 |
| `game/presentation/foliage/ui_typography.tres` | 沿用全项目共享字体与字号层级 |

精确接口和事件顺序见 [BUILD_IMPLEMENTATION_CONTRACT.md](BUILD_IMPLEMENTATION_CONTRACT.md)。模块读取工厂注入的目录，不在每帧或命中时读取JSON/全局Registry。

## 运行规则

- 普攻 `committed` 建立本次施放的构筑与伤害快照；`cue_reached` 请求剑气；近战确认扣血后请求连锁。后续选择不追溯修改已飞出的子弹。
- 战斗主循环先推进角色/能力，再解析近战，再消费构筑派生队列；清波的选择面板在当前步骤完成后打开。面板不从击杀信号内同步打断解析。
- 同一施放及其全部子弹共用根预算；每步请求数、队列长度、活跃子弹、每根子弹数与分裂代数都有显式限制。派生通过队列执行，禁止递归调用造成无限触发。
- 连锁目标按距离、再按运行时handle稳定排序；每个连锁升级每根至多触发一次。连锁不能再触发连锁或分裂。分裂子弹排除父命中的目标及祖先排除目标。
- 剑气采用连续扫掠，墙体先截断移动路径；不会因单帧穿过目标而漏检。当前平面战斗以角色中心为受击点，玩家派生子弹不具备自动绕障；敌人地面导航由房间模块注入。
- 发射者死亡遵守JSON策略；当前配置清理其派生效果。清房、重试、离场清除上下文及展示节点，旧房间请求不可复活；过期子弹不造成伤害。
- 候选不足时允许少于三张，空池不打开模态。已存在未选offer时复用；切语言不推进随机数。等级、标签和显式前置从空构筑开始必须可达；互斥复杂组合仍需内容试玩验证。
- 当前训练将“普通暂停”和“三选一暂停”共同门控规则与表现；没有新增全局time_scale。统一冒险的嵌套暂停令牌由后续主会话接入，本轮不宣称已完成通用TimeAuthority。

## 后续添加正式技能

**已有机制的数值/名称变体**：新增稳定升级ID，使用已实现的effect_type，填完整ranks、前置/互斥/标签，加入pool_ids，补双语名称/描述，运行内容工具并重新训练。不要改既有ID语义来模拟迁移。

**新机制**（燃烧、护盾、主动槽位等）：先明确触发来源、叠层/继承/取消/预算规则，再扩展schema、运行时和离线校验、resolver/runtime处理器及测试；JSON不能凭空声明尚未实现的类型。本切片每条升级有一种effect_type，不支持任意表达式或脚本组合。

**美术替换**：只修改 `presentation/builds` 的Resource或表现适配器，消费投射物快照/连锁事实，不从粒子碰撞或动画帧直接扣血。

**正式冒险保存**：当前注入内存提交器，session对提交失败保持权威状态及RNG不变，已有失败注入测试。接正式Run时仍需实现磁盘保存、内容版本兼容、已生成候选恢复和清房奖励事务；现在重新打开游戏不会恢复训练Build。
