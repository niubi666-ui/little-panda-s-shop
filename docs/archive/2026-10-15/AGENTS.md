# 项目开发入口

先读精简版 [PROJECT_CONTRACT.md](PROJECT_CONTRACT.md)，再读 [docs/HANDOFF.md](docs/HANDOFF.md)；按其中索引只读任务涉及的模块。已有同版本上下文无需重复整篇读取。不要默认扫描所有 Markdown、归档、素材说明和旧日志。

## 必须遵守

- Godot 根目录 `game/`；`source_assets/`、`concepts/` 在引擎项目外。用户最新决策优先。
- 玩法/经济/AI/构筑数值来自 JSON；表现来自 Resource。同字段一个权威来源；禁止隐藏内容默认值。技术常量、枚举、索引和运行状态初值可在代码。
- 内容先校验，再解码为只读定义并注入；不按帧读 JSON，不用全局服务定位器。规则与表现分离，命令显式调用，事实用局部 signals。
- combat 执行构筑；rogue 抽候选和生成计划；app/session 协调跨模块提交。持久变更必须隔离候选，保存失败不改变权威状态及 RNG。
- 逻辑时间线决定命中；派生效果共享根预算及来源限制。生成需锁定计划、验证可达性，视觉随机不消耗玩法随机流。
- 翻译 JSON 是人工源，PO 由工具生成；玩家文本用 key 与命名参数。存档使用稳定 ID/值，兼容性错误不能伪装损坏静默回退。
- 同一文件同一时刻一个写入者；并行任务声明可写范围、接口和验收。公共契约、schema、根场景、project.godot、导出配置由整合者协调。
- 未经用户明确要求，不生成 Release。不要操作其他对话正在使用的 Godot/Blender 进程。
- Git 使用 GitHub 与 LFS 同步项目；只有用户明确要求时才可 commit、push 或修改远端，本次授权不代表未来自动提交。入库范围见 [版本管理](docs/LOCAL_GIT.md)。
- 只运行与改动匹配的验证。交付区分实际实现、历史通过和未验证；计划/概念图不等于实现。

## 文档维护

稳定规则改契约；当前接口/配置改模块文档；未解决问题改 [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md)。HANDOFF 只保留状态与索引，不追加逐轮日志。历史放 `docs/archive/`，不作为当前实现依据。
