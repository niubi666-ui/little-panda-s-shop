# 构筑能力适配契约

2026-10-02。当前schema v5已按`primary/special`绑定；详细接口见[Build API](../BUILD_IMPLEMENTATION_CONTRACT.md)，触发与状态语义见[命中机制](../COMBAT_MECHANISMS.md)。本页维护扩展边界，不重复配置表或验收记录。

## 1. 能力是可执行契约

通用机制不依赖武器名或测试卡ID。标签只做分类；能力必须有合法定义、适配规则和执行器。content校验只读定义，combat编译/执行，rogue拥有池与随机，app协调提交，presentation消费事实。

- 箭、剑气、法术弹可共用直线投射物处理器；光束分叉、召唤分身需各自执行机制，不能只贴“分裂”标签。
- 动作形式引用能力/投射物定义，并明确melee或projectile执行路径；形态改造替换当前执行方式，不用0伤害伪造禁用近战。
- 每动作至多一个核心；支持、协同分别绑定动作。global只表达明确的角色属性修正，不作为另一个隐式攻击。
- 工厂负责对象构造，效果处理器负责修正与触发；不引入每卡常驻Node、服务定位器或配置脚本。新的形态/处理器先补schema与校验，再开放卡池。

## 2. 必须匹配同一实际携带者

资格来自**目标动作当前形态及已授予载体**，不受当前冷却、场上是否已有子弹或目标是否免疫影响。

- 摘要保留action、attack、origin、状态与范围源的关联；禁止把不同动作的能力并集拼出不存在的携带者。左键冻结不能满足右键冻结强化，T调试箭不能满足正式右键穿透前置。
- 直接冻结与爆炸内冻结是两条携带路径。寒霜协同须匹配本动作对应的爆炸源；普通爆炸不自动继承直击状态。
- Resolver纯评估复用于候选、预设、替换、提交与程序验证；替换先移除旧项再全量复验，任何旧依赖失效都拒绝并返回原因。当前不自动删卡、退款或挂起。
- 候选锁定目标动作、操作、新等级、旧选择和revision；提交复验同一绑定，不能由UI改目标。rogue只决定升级权重与合法绑定采样，不复制兼容规则。
- 同一升级可独立绑定左右键；各自升级新级替换旧级。按升级ID先抽样，不能因两个动作可用而翻倍权重或占满同轮候选。

## 3. 派生继承与完整组合

接触、HP实损、碰墙是不同事实。发射挂在逻辑cue上，挥空也可发射；动画、粒子和武器模型不能决定命中。

- 每次施放截取action/form/revision、伤害、效果与表现键。子体保留根动作归属和快照，同时保留自身origin/代数；拥有动作身份不自动获得所有来源权限。
- 全局与动作增伤按配置相加后限幅一次；子体/爆炸基于父快照，不再套全局倍率，不用目标HP实损代替父伤害。
- 子体类型/运动/寿命/排除集合的继承逐字段定义；各分支共享根预算，还受触发次数、代数/跳数、visited、队列和存活对象上限约束。定义自引用不意味着无限派生。
- 当前**同一动作计划，包括其派生载体**禁止穿透＋分裂、分裂＋寒霜；不同动作可分别拥有。寒霜是有限范围payload，不是第二核心。完整集合需要验证，不能只凭两两兼容放行。
- 范围payload不伪造通用接触，不递归触发爆炸/连锁。直接控制和范围控制经过同一状态入口，两动作共享目标抗连控；根预算与抗连控分别解决请求上限和可行动窗口。

取消、死亡、暂停、清房和根回收遵守[战斗扩展](COMBAT_AND_BUILDS.md)。当前调试wave/chain只在明确夹具动作中复用同一编译体系；尚未实现任意技能图、同动作穿透分裂混合或正式换装事务。
