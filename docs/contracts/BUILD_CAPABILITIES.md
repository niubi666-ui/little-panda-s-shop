# 构筑能力适配：投射物与有限范围效果

2026-10-02。**设计契约，直线投射物分裂/穿透、有限复合范围与候选适配已实现；其余扩展仍是目标。当前 schema v4/API 以实现契约为准。** 实现现状见 [Build概览](../BUILD_SYSTEM.md)，现有签名见 [Build API](../BUILD_IMPLEMENTATION_CONTRACT.md)。本页只在扩展通用构筑、武器能力或候选资格时阅读。

## 1. 设计边界

武器大类决定基础操作，变体提供起始特色，局内Build改变行为。少量武器与共用机制优先验证；武器数量、剑/弓/法杖名单和具体路线均未定，不预建完整职业树。

效果依赖对象实际支持的能力及适用范围，不依赖武器名、卡名或固定的剑气升级ID。现已共用投射物分裂/穿透与状态处理；光束分叉、召唤物分身属于不同机制，需要各自契约，不能仅贴上同名标签就复用。

## 2. 定义与模块责任

下表是概念职责。已实现字段、固定策略与签名见Build API；没有在该API列出的字段不能直接写入JSON。

| 概念 | 拥有的内容 | 责任 |
|---|---|---|
| 投射物定义 | 运动/碰撞规则、基础参数、能力声明、子体定义或生成策略引用、表现ID | content校验；combat执行 |
| 能力描述 | 支持哪类变换、允许的来源与触发、注册执行器引用 | 规则配置声明，代码提供实际实现 |
| 分裂升级 | 适用范围、时机、数量、角度、伤害系数、次数/代数与继承规则 | combat解析为执行计划 |
| 能力摘要 | 当前装备和已授予技能实际可产生的攻击及其能力、来源关联 | combat纯解析；app注入候选流程 |
| 兼容性查询 | 升级能作用于哪些攻击，不能作用的原因 | combat提供同一规则；rogue与UI消费 |
| 分裂请求 | 父实例、方向、子体参数、继承快照与根上下文 | combat有界队列与生成器处理 |
| 表现映射 | 箭、小剑气、法术弹等模型/特效 | presentation消费快照/事实 |

数值与业务规则来自JSON，模型/材质来自Resource。工厂注入只读定义与执行器；不增加全局服务定位器、每卡常驻Node或任意脚本配置。

标签用于分类筛选；“可分裂”能力必须能解析到合法子体和实际执行器。加载时校验引用、类型适配、策略、范围和预算，只有标签而无实现时拒绝内容。普通箭/剑气/法术弹优先共用生成器，通过数据区分；特殊运动才增加有界的注册适配器，不按武器名字分支。

## 3. 统一请求，不抹平对象差异

公共运行信息包括来源角色/技能、位置/方向、速度/寿命、伤害与Build快照、碰撞/命中规则、能力、根上下文。光束和近战无需硬塞进投射物结构。

分裂效果负责“是否分、何时分、分多少、怎样修正”，父对象定义/适配器负责“生成什么子体、如何初始化”。例如箭生成箭，剑气生成小剑气，法术弹生成对应子弹；分裂处理器本身不判断武器或技能ID。

流程：合法碰撞事实 → 匹配能力与升级范围 → 检查次数/来源/预算 → 排队分裂请求 → 生成器验证并创建子体 → 表现层显示。

碰敌、碰墙、造成有效伤害是不同触发条件。首次实现明确选用哪一种，不能把“接触”自动等同于“造成伤害”。父体穿透/销毁规则与分裂独立；分裂不自动附送穿透或连锁。

## 4. 候选与执行共用兼容性规则

纯分裂升级进入卡池的条件：当前装备和已取得能力中，至少有一种可实际使用的攻击，在该升级适用范围内支持分裂。检查长期能力，不要求场上此刻有飞行中的子弹，也不因技能短暂冷却就判无能力。

- 只有近战：不出现；获得可分裂剑气：出现。
- 已装备能发射可分裂箭的弓：无需先选剑气即可出现。
- 只有不可分裂光束：不出现。
- 同时拥有两种兼容攻击：按升级范围分别生效；不兼容攻击保持原规则。
- 摘要保留每种攻击的关联信息，不能把两个对象的标签取并集，错误地拼出一个实际不存在的可分裂对象。

兼容性检查包含同一套能力、来源、升级范围规则；候选对能力描述查询，运行时对本次施放快照中的实际对象查询，并额外检查碰撞、触发计数和预算。不得让rogue另写一套“有投射物即可”的规则。

rogue继续拥有卡池、等级/前置/互斥、权重与随机抽取；combat不负责抽卡。配置可为确有设计意义的专属升级保留指定前置，但通用分裂不能被固定剑气ID阻塞。

UI可展示当前受影响的攻击，使用稳定ID映射翻译。能力与候选基于同一构筑修订版。首个切片在待选面板期间禁止装备/技能变更；以后支持变更时，需事务化重验，不能静默重抽已发布候选。暂不引入战斗中换武器。

## 5. 子体继承与组合限制

在内容中显式决定以下规则；无字段时加载报错，不由对象各自猜测：

- 继承父施放的伤害/Build快照与归属；已经计算的加成不得再乘一遍。子体伤害基数及分裂系数的应用位置统一约定，不混用扣血量与发射伤害。
- 同根共享预算句柄，分支不得复制满额预算；来源、次数和代数决定合法玩法，预算只是额外保护。
- 记录分裂代数、每对象/每升级触发次数与祖先排除目标。推荐首个切片每对象每分裂升级最多触发一次，并显式配置。
- 子体能否再分裂、连锁、施加状态，各自按能力和来源规则检查。通用能力不表示允许无限传播；自引用子体定义只有在有界派生校验通过后才合法。
- 寿命、速度、碰撞半径、穿透/反弹次数等逐字段定义继承或覆盖；新增字段必须补充继承策略。能力与子体类型来自合法定义，不盲目复制父对象全部状态。
- 区分防止立即重撞的排除集合与伤害去重组。不同子体通常各有命中实例；若设计为同根只伤一次，使用显式共享组。
- 父体销毁不销毁仍被子体/队列持有的根上下文。取消、发射者死亡、换房遵守 [战斗扩展](COMBAT_AND_BUILDS.md) 的统一生命周期。

当前穿透/分裂是全局升级，内容要求对称excludes，候选/提交/执行一致拒绝并用；这是原型收紧，并非完整按动作绑定。穿透用每弹visited与总命中额度，爆炸每弹首次接触一次，直接冻结可逐目标申请；三者计数分别负责各自规则。未来开放更多组合前，先规定叠加/互斥、执行顺序及子体来源，不能依赖JSON顺序或只靠安全预算。

## 6. 历史迁移与当前边界

v1曾依赖测试剑气ID和projectile标签；v2迁到定义/子体引用/统一查询并完成剑气＋测试箭共用分裂，用户已确认实机通过；v3加入爆炸/状态。当前v4加入穿透、目标侧抗连控及寒霜范围payload，加载器明确拒绝v1/v2/v3；完整字段以Build API为准。

当前摘要逐攻击保留origin、直接status_ids、modifiers及area_effects内的source_effect_id/status_ids。寒霜必须匹配同一真实携带者上已选爆炸的来源；冻结延长同时识别直接或范围携带者，不能跨攻击拼标签。候选查询还编译下一等级组合，提交复验共用该路径。短暂冷却、场上是否已有状态和目标是否免疫不改变长期能力资格。

普通爆炸不隐式继承直接冻结。只有area_status显式协同才能给相应explosion编译apply_status payload，且不产生通用接触事件；不递归产生爆炸、分裂或连锁。当前样本只改直接近战/直接投射物的爆炸，分裂子体仍普通爆炸。目标侧统一冻结组限制活跃续时及解冻抗冻，来源切换或新卡不能绕过。

已落地范围、规则和验证见 [命中机制](../COMBAT_MECHANISMS.md)。仍未实现完整装备/职业授予框架、按动作绑定/主动AOE、运行中换装事务、复杂运动适配器、UI逐攻击兼容原因、正式存档；不把本页扩展目标当成已完成能力。
