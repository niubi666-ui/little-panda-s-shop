# 战斗与构筑扩展约定

更新：2026-10-01。只在改变执行机制时读取。当前接口见 [战斗](../COMBAT_PROTOTYPE.md)、[敌人](../ENEMY_ROLES_AND_ENCOUNTERS.md)、[Build API](../BUILD_IMPLEMENTATION_CONTRACT.md)。**以下包含待实现目标**：完整通用Status、多分量伤害、Boss策略和统一时间服务不能当成现有能力。

当前已完成slow/freeze最小状态实例、命中范围伤害及必要的五类敌人控制接入，具体固定规则见 [命中机制](../COMBAT_MECHANISMS.md)；不代表以下所有扩展已经完成。

## 1. 组合与执行权

角色组合意图源、状态许可、Motor、技能执行器、命中/伤害、属性/状态、Build和表现；仅需场景/物理生命周期的组件使用Node。避免按武器、元素、皮肤继承整套角色。

| 部件 | 权威职责 |
|---|---|
| 意图源/决策策略 | 提出移动、朝向、攻击意图 |
| 状态机 | 意图许可、中断与优先级 |
| Motor | 唯一移动、碰撞、冲刺、击退与朝向仲裁 |
| 技能执行器 | 前摇/生效/后摇、消耗、冷却、取消 |
| 命中检测 | 收集接触并请求结算，不直接扣HP |
| 伤害结算 | 合法性、阵营、无敌、去重、伤害与死亡转换 |
| 状态/Build | 属性、持续效果、执行计划与触发计数 |
| 表现 | 模型、动画、预警、音效、震动 |

现用近似同平面3D战斗，无自由空战/根运动；普攻允许移动，倍率由能力配置。引入根运动需经Motor适配。

## 2. 施放、命中与事实

意图 → 状态许可 → 施放快照 → 前摇/配置的承诺点 → 逻辑生效点 → 接触校验/去重 → 提交伤害 → 伤害/死亡事实 → 有界派生队列 → 表现与后摇。

消耗/冷却的承诺点及取消退款由能力定义；输入、动画和角色脚本不能重复扣费。施放后更新Build不改变已发射对象；目标防御在命中时读取。

- 命中去重包含cast、命中组实例与目标。一次挥砍的多个形状共享组；独立子弹/脉冲各分配实例；散弹只伤一次等要求显式共享组。
- 未来多伤害分量统一提交，一次产生DamageApplied；分别记录护盾吸收、HP实损与过量伤害。扣血、无伤接触与护盾受击是不同触发条件。
- 逻辑事件需能关联施放/来源/目标/房间代数；接触不等于伤害成功。ActorKilled只在存活转死亡时发一次。
- 遭遇清场要求全部波次结束、待生成数为零、计入遭遇的存活集合为空。卸载/取消不是胜利，波间空场不能提前发奖。

## 3. 构筑与能力适配

Ability定义动作；Upgrade定义修正/授予/触发；Status定义持续效果。状态只记录已选ID/等级与运行数据，Resolver编译执行计划；战斗不按卡名判断。新增真正机制需要注册处理器与schema，不允许配置任意脚本或公式。

**跨武器分裂、能力摘要及候选兼容性只在 [BUILD_CAPABILITIES](BUILD_CAPABILITIES.md) 维护。** 当前v3仍是训练原型，现有前置和执行语义见Build API，不把测试剑气依赖推广为正式规则。

伤害类型与玩法标签使用稳定内容ID；抗性按类型映射，缺项行为来自显式配置，不固定四元素枚举。附加与转换伤害分开；近战命中、逻辑发射时间点、投射物碰撞等使用各自挂点，挥空发射不能依赖先命中。

属性扩展目标：
~~~text
clamp((基础值 + 固定加值之和)
      × (1 + 同组百分比之和) × 独立倍率之积,
      配置下限, 配置上限)
~~~
修正按稳定ID排序，带来源；移除后从基础重算，等级替换旧级。当前v3支持范围仍以API为准。

状态机制新增时定义stack_key、叠层/时长/tick策略、层数上限、来源快照和生命周期；实例剩余时间不能写回共享定义。主动槽位满额需明确替换，不静默覆盖；组合解锁规定优先级/互斥，相同已选集合应得到相同解析结果。

## 4. 派生上下文与生命周期

上下文需能关联run/房间代数、事件/父事件/根动作、cast/命中实例、来源/归属/目标、能力/效果/触发器、位置方向、来源标签、数值与Build快照、触发深度/祖先链和根预算。字段按实现需要建立，不先造通用空壳。

- 运行时实体句柄带代数，防对象复用后的旧请求误命中；不保存为永久身份。
- 同步伤害回调不能递归执行派生。使用有界队列，同时限制事件来源、每触发器次数/冷却、祖先重入、分裂代数、连锁跳数/visited、单步/队列/存活对象上限。
- 根预算共享且不随分支或状态tick重置，由所有子体/状态/排队请求共同持有，最后一个释放后回收。预算计量单位固定为派生执行请求，普通移动帧不计入。
- 连锁目标按距离、再按稳定运行时标识排序；旧房请求无效。发射者死亡后保留或清理已发射对象由配置明确决定。
- 普通合法构筑不能频繁耗尽保护预算；超限拒绝策略确定、可诊断。玩法限制外置，技术上限可以明确常量/资源表示。

正式切房目标：取消施放、子弹、排队命中、房间临时状态与计数；保留HP/Build及配置要求的资源/冷却。清理与过渡后创建入口快照；地图/选卡阶段不推进战斗冷却。跨房状态另设run作用域及迁移，不能携带旧房代数。正式提交见 [状态与存档](SESSION_AND_SAVE.md)。

## 5. 候选与提交

rogue拥有卡池/等级/前置/互斥过滤及随机抽取，兼容性消费combat规则；app协调选择提交。按唯一升级ID无放回，数量与fallback来自配置；不足可展示较少项，空池不伪造重复卡。发布前验证可达卡池。

候选在显示前锁定ID、已滚值与随机状态，选择验证offer/candidate和修订版；选择与Build作为一次提交，切语言/重开面板不重抽。当前是训练内存提交，正式磁盘恢复按状态存档契约实现。

## 6. 敌人策略与状态机

目标：感知快照 → 决策策略提出意图 → 状态机许可 → 技能执行器/Motor执行。Alive下可含Idle、Seeking、Repositioning、Acting、Staggered，外层含出生/死亡/退场。Boss阶段改变动作池与策略参数，不复制整套执行器。

目前近战/重型沿用AbilityRunner，弩手/矛兵/旗手有专用逻辑状态机；通用目标不代表已全部迁移。

- 死亡优先于可生效硬控和动作，霸体不能免死。统一取消清理命中窗口、预警、位移、待执行时间点和表现。
- Acting读取技能阶段，不重复维护一套攻击计时器。动画状态机不承担AI决策。
- 延迟回调携带施放/实体代数；目标失效、离房、不可达或导航堵塞需返回/重试路径，更新间隔与超时来自AI配置。
- 起手锁定、持续追踪或承诺点锁定由能力声明，预警与实际一致；Boss阶段转换是否中断仍遵守动作规则。
- 新动作扩执行器，新决策扩策略；模型/元素变体主要组合定义与参数。

## 7. 动画与时间

逻辑时间线裁定命中，动画只映射并同步阶段；动画轨道不扣血，animation_finished不能是唯一退出条件。材质/动画运行状态按实例隔离。

未来统一时间服务管理嵌套暂停令牌，冻结规则、移动、AI、派生队列与表现，UI仍可操作。顿帧令牌必须由不受暂停的时钟释放，不能用已冻结时钟恢复自身；暂停期间物理请求排队，恢复重验。

动作缓冲需明确期限；菜单/三选一禁止Gameplay输入，慢动作走同一入口，禁止各脚本直接改全局time_scale。当前训练暂停能力及局限以模块文档为准。
