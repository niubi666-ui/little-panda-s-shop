# 战斗与构筑扩展约定

2026-10-02。当前按动作绑定的v5接口见[Build API](../BUILD_IMPLEMENTATION_CONTRACT.md)；基础战斗、敌人和范围/状态细节分别见[战斗](../COMBAT_PROTOTYPE.md)、[敌人](../ENEMY_ROLES_AND_ENCOUNTERS.md)、[命中机制](../COMBAT_MECHANISMS.md)。本页包含扩展约束，不代表完整Status、伤害分量、Boss策略或统一时间服务已实现。

## 1. 执行权与逻辑时间线

角色组合意图、状态许可、Motor、技能执行器、命中/伤害、状态/Build和表现，不按武器/皮肤继承整套角色。仅需场景/物理生命周期的组件使用Node。

| 部件 | 权威职责 |
|---|---|
| 意图源/敌人策略 | 提出移动、朝向、动作意图 |
| 状态许可/AbilityRunner | 仲裁、中断、逻辑阶段、承诺点、独立动作冷却 |
| Motor | 唯一执行移动、碰撞、冲刺、击退 |
| 命中/伤害 | 接触收集、阵营/无敌/去重、伤害与死亡 |
| 状态/Build | 持续效果、纯选择评估、快照、触发计数 |
| 表现 | 模型、动画、VFX、预警、声音与震动 |

流程为意图→许可→施放快照→逻辑cue→接触校验与提交→事实→有界派生队列。伤害和发射由规则时间线决定；目标防御在命中时读取，后续Build变化不追改旧cast。一次挥砍多个形状共享命中组；独立子弹各有实例，共享去重需显式声明。

当前剑动作：primary三连击、special点击重斩或剑气形式、dodge沿用闪避。一身体一个Runner；同帧优先闪避→special→primary。primary独占连段进度，special开始时重置；动作冷却相互独立，变更形态不刷新剩余冷却。

- 忙碌时只有一个带action_id的有期限缓冲，后到有效意图替换；进入模态、死亡和重试清理缓冲。缓冲时长、移动倍率与闪避可取消阶段来自能力JSON。
- 当前承诺点为start，冷却开始后取消不退款；重斩/剑气仅允许起手与恢复闪避取消。cue前取消不发射；已发射对象遵守原快照和生命周期。
- 投射物形态跳过近战及房间物件的近战命中路径；0实损仍是合法接触，所以不能通过damage=0禁用。
- 当前只用剑程序姿态，角色保留idle/run。AttackMotion与Resource映射消费逻辑阶段/事实；骨骼动画未来可替换适配器，动画轨道不扣血，animation_finished不是唯一退出条件。
- 当前近似同平面3D战斗，攻击允许移动；未来根运动必须经Motor适配。接触、护盾受击、HP实损是不同事实；多分量伤害/护盾结算尚未实现。

## 2. 构筑与状态扩展

Ability定义动作时序/伤害，形态引用能力和执行方式，Upgrade按动作或global绑定，Status定义持续效果；运行状态与只读目录隔离。Resolver从绑定选择和revision派生槽位与计划，不保存第二份可变槽位真相。跨武器及同携带者资格见[能力适配](BUILD_CAPABILITIES.md)。

- 每动作至多一个核心；形态、支持、协同职责分开。完整集合按稳定身份编译；新等级替换旧级。替换令现有支持/协同失效时拒绝，不静默删除退款。
- global与动作增伤按配置加和/限幅，角色移速单独应用；不能在根和子体重复乘倍率。效果来源与表现键随施放快照保留。
- 伤害类型/玩法标签使用稳定内容ID，不固定元素枚举。新增附加/转换伤害先定义合成顺序；新状态先明确叠层、时长/tick、上限、响应和移除规则，不能仅贴标签。
- 当前slow/freeze从剩余状态重算许可；状态剩余时间不写共享定义。冻结同根去重与目标跨根抗连控是独立规则；两动作交替不能绕过同一目标的解冻免疫。
- 范围状态须经显式有限payload授权；冻结核心不会自动感染所有爆炸。更复杂主动槽、DOT与任意技能图仍需新增机制及验证。

## 3. 派生上下文与生命周期

上下文按需关联房间代数、cast/root、action/form/revision、来源/目标句柄、origin、效果和预算，不预造万能EventBus。运行时句柄不能作为永久存档身份。

- 同步伤害回调不递归执行派生；使用有界队列并限制来源、次数、代数/跳数/visited。子体不复制满额预算；最后一个施放/投射物/请求引用消失后回收根。
- 当前slow/freeze保留来源值和弱目标；未来DOT须另定根存活规则。有限复合范围的预算计量见命中机制，不能把每个状态目标暗变为新根。
- 派生目标稳定排序，过期房间请求无效；同步回调可能清房/死亡/移除，回调后需重验上下文。卸载/取消不是胜利，波间空场不是完成。
- 每实例表现有独立cast/投射物身份；暂停冻结，取消结束剑轨迹，清房回收场景节点。自定义VFX遵守时间/结束协议；禁用表现不影响规则。

当前训练仍整场景重试。正式跨房目标为取消房间施放/子弹/排队命中与临时状态，保留HP、Build及配置要求的资源/冷却；跨房状态另设run作用域，不能携带旧房代数。入口快照/正式提交遵守[状态与存档](SESSION_AND_SAVE.md)，不能从训练内存提交推定已实现。

## 4. 候选与提交

combat唯一纯评估、rogue采样、app/session提交。候选锁定choice_id、升级、目标动作、操作、新等级、完整被替换项与base_revision；UI只提交offer/choice令牌，切语言不重抽。

先构造隔离候选、全量校验/编译，再提交；成功才发布Build/program/revision。过期/重复/伪造及提交失败保留权威状态和RNG。预设和程序校验也复用该评估器；当前训练仅内存适配，正式持久恢复遵守存档契约。

先按升级ID无放回抽取，再在合法绑定操作中按配置选目标；能绑定两个动作不应翻倍权重。fallback也必须有效，候选不足允许少于三项。训练开场/清波选择不等于未来冒险每房发祝福，路线节奏见[房间与奖励](ROOM_GENERATION.md)。

## 5. 敌人决策、取消与时间

敌人目标结构为感知快照→策略意图→状态许可→技能执行器/Motor。Boss阶段未来通过动作池/策略参数改变行为，不复制执行器；当前实现以敌人文档为准。

- 死亡优先于硬控和动作；取消统一关闭命中窗口、预警、位移、待执行cue及表现，解控不得恢复旧攻击。
- Acting读取逻辑技能阶段，不维护另一套计时器；动画状态机不承担决策。锁朝向/追踪策略与预警须一致。
- 延迟回调携带施放/实体代数；失效目标、离房、堵塞采用明确返回或有界重试，间隔来自AI配置。
- 当前训练门控同时停止角色、AI、技能、队列与表现时间，UI可用；尚非通用嵌套暂停服务。未来慢动作/顿帧使用统一入口，各模块不能独立改全局time_scale。
