# 古树圣庭 v003 · 落叶降面与面数审计

2026-10-02。以 v002 已保存工程为只读来源；独立 Blender 5.2.1 后台进程制作。原始 v002 保留，Godot 未改动。

## 打开与对比

- [无透明法线版](blender/grand_forest_sanctuary_v003_leaf_opaque_normal.blend)：保留八点叶片轮廓，用烘焙法线模拟隆起；建议作为保守的 Blender 美术候选。
- [透明贴片法线版](blender/grand_forest_sanctuary_v003_leaf_cutout.blend)：每片两个三角形，透明裁切保留轮廓，适合后续引擎内比较。
- [原版／两种候选同机位对比](previews/index.html)。这是实际 Cycles 渲染，未用图像生成代替验证。

两份都保留 12,421 片落叶的分布、方向、尺度及五种原始材质分配。共同变化是去掉真实中央隆起，以法线表现起伏；极近、低角度的立体轮廓与真实高模仍有差别。

| 落叶方法 | 每片三角面 | 总三角面 | 相对落叶原版减少 | 新材质成本 |
| --- | ---: | ---: | ---: | --- |
| v002 原版 | 8 | 99,368 | — | 原始程序材质 |
| 无透明法线 | 6 | 74,526 | 25% | 法线采样，不使用透明裁切 |
| 透明贴片法线 | 2 | 24,842 | 75% | 法线与轮廓采样、透明裁切 |

法线负责受光的凹凸变化，不能单独裁出叶片轮廓。透明贴片版依靠不透明度纹理裁切；无透明版用网格保留轮廓。贴图均由现有单叶模型在 Blender 中烘焙，512×512，已打包。原有程序颜色与细微凹凸继续使用。

## 性能结论与限制

首次逐个渲染近景时，原版 10.74 秒、透明版 20.32 秒；初始化、编译和缓存会影响这种单次计时。因此又在同一独立进程中，对三种方法各渲染两次、启用持久数据，记录第二次预热后的耗时：

| 方法 | 同机位预热后 Cycles 渲染耗时 |
| --- | ---: |
| 原版 | 3.245 秒 |
| 透明贴片法线 | 3.319 秒 |
| 无透明法线 | 3.242 秒 |

条件：Cycles OptiX、900×562、32 samples、同镜头/灯光/场景；每种只有一次预热后的样本，不能据此声称统计显著的提升。**本次证明的是降面和外观接近，没有证明游戏或整个 Blender 场景明显提速。**透明材质会增加像素与阴影处理成本，减少三角面不一定更快。实际 Godot Forward+ 帧率、导入与LOD尚未验证。

## 真正的几何开销集中处

v002 基础网格按对象累计展开共 29,536,447 三角面（包含视野外对象，未按相机裁剪，不等于每帧提交量）。截图视口 608,384 采用已求值网格去重统计；两者不能混用。

| 白花＋紫花 | 9,185,059 | 31.10% |
| 蕨类 | 7,753,728 | 26.25% |
| 苔藓贴块＋缝隙苔藓 | 4,949,396 | 16.76% |
| 额外白铃花喷簇 | 3,428,854 | 11.61% |

前四项合计约 85.71%。这些已使用共享网格，进一步减少重复存储并不能消除每个实例的绘制开销。下一轮应优先制作花簇/蕨类低模原型与LOD，将薄苔藓转换为材质细节或低面片，并处理地砖不可见底面。沿用既有密度和景观，先比较代表性样块再替换共享原型。详细分类和建议见[性能审计](reports/performance_audit.md)。

## 为什么选中的树干显示零面

截图中的 `Forest_oak_7__SacredOak_Trunk_Preserved` 确实是 Mesh，不是空物体。它有 19,032 三角面，13 个树干对象共享同一原始网格；后台还验证它们的已求值网格指针只有一个。

Blender 5.2.1 对象模式统计先对已求值 Mesh 去重，再累计选中几何。若同网格的未选副本先被计数，后面的选中副本会被略过，从而显示选中 0 面；这不表示该树没有几何或渲染成本。[对应官方源码](https://github.com/blender/blender/blob/v5.2.1/source/blender/editors/space_info/info_stats.cc#L158-L171)。
